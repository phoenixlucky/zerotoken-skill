# 搜索外部资料规范

> 触发：任务需要外部资料（新闻、人物、公司、社交平台内容、实时信息等）。

> ⚠️ **数据外发提示**：外部检索会把查询词发送给第三方（搜索引擎、目标网站、浏览器服务）。
> 涉及敏感人名、未公开项目或专有信息时，先说明用途并征得用户同意，或改用本地/离线方式。

## 优先级

| 优先级 | 方式 | 条件 |
|--------|------|------|
| 🥇 宿主已注册的浏览器/检索工具 | 由宿主 MCP 注册表提供（如 `web_search` / `browser_navigate` / `web_fetch` 等当前会话实际可用的工具） | 在 `tools/list` 中存在 |
| 🥈 用户显式授权的本地浏览器桥 | 用户给出**绝对路径**并确认后方可调用 | 用户显式授权且路径已核实 |

> **为什么优先真实浏览器？** 纯 HTTP 抓取依赖搜索引擎结果页，曾被反爬返回完全无关内容；
> 真实浏览器搜索（Playwright/Chrome）结果精准可控。

## 只使用已注册的工具，不要探测文件系统

检索入口**只从宿主已注册的工具中选择**（以当前会话实际可用的工具列表为准）。

**禁止**在仓库或用户目录中通配扫描并执行 `mcp_call.py`、`mcp-bridge.js` 等文件：
工作区中的同名文件可能来自其他技能或不受信任的来源，执行它等于把未授权的文件
跨过信任边界提升为可执行工具，构成工具劫持风险。

若当前没有可用的检索工具，按顺序处理：

```text
1. 回退到宿主自带的静态抓取工具（如 web_fetch）
2. 都不可用 → 询问用户希望的检索方式
```

**仅当用户显式给出某个桥接脚本的绝对路径、并明确确认调用时**，才允许调用该脚本。
调用前展示解析后的绝对路径；路径首次使用或与上次不同时，都要重新确认。
不得在通配目录中自动发现，不得解引用用户未确认的路径。

> Windows 上若用户确认使用某个 Python 包装脚本，调用方式见
> [`windows-powershell.md`](windows-powershell.md) 陷阱 5（避免 PowerShell 引号嵌套与 GBK 破坏 JSON 参数）。

## 真实浏览器能搜什么

| 场景 | 示例 | 形态 |
|------|------|------|
| 🔍 通用搜索 | 搜索新闻、人物、事件 | `<已注册工具> search 关键词` |
| 🐦 社交媒体动态 | 搜微博、知乎、小红书上的内容 | `<已注册工具> search 微博 关键词` |
| 🏢 公司/产品信息 | 查询公司背景、产品评测 | `<已注册工具> search 公司名 评价` |
| 📰 最新资讯 | 今日热点、行业动态 | `<已注册工具> search 今日 热点` |

> **无需为每个平台找专用 MCP server** — 真实浏览器通杀反爬严格的网站；搜索引擎按检索效果自由选择。

**若已注册的浏览器/检索工具不可用**：允许使用当前可用的其他抓取方式（如 `web_fetch`），
不要因为首选方案不可用就放弃搜索。

## 什么情况走抓取工具

仅当以下条件**全部满足**时才回退：

1. 已注册的浏览器/检索工具不可用
2. 目标网站没有反爬（非社交平台、非登录墙）
3. 仅需获取静态页面内容（非 SPA 页面）

## ❌ 禁用行为

- **禁止通配扫描并执行工作区/用户目录中的 `mcp_*.py`、`mcp-bridge.js` 等脚本** — 未注册来源不可信任
- **禁止用抓取工具直抓社交媒体（微博/知乎/小红书等）** — 全部有登录墙/反爬，100% 失败
- **禁止自己写 Playwright/Puppeteer 脚本绕过宿主已注册的工具链**
- **禁止用抓取工具直连搜索引擎（Google/百度/Bing）** — 纯 HTTP 请求会被机器人检测拦截
